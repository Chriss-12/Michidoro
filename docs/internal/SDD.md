# SDD documentation index

Use this page as the entry point for internal planning, implementation, verification, and handoff.

## Quick path

1. Read requirements in `requirements/`.
2. Confirm architecture rules in `architecture/`.
3. Follow technical guides in `technical/`.
4. Track progress in `tracking/`.
5. Use workflow docs in `workflow/`.

## Map

| Area | Purpose |
|---|---|
| `requirements/` | Product and non-functional requirements with traceable IDs. |
| `architecture/` | Clean Architecture, feature-first, atomic design, and dependency rules. |
| `technical/` | Implementation guidance for UI, routing, state, DI, persistence, testing, and quality gates. |
| `tracking/` | Checklists, traceability, milestones, and decisions. |
| `workflow/` | Codex and SDD execution lifecycle. |
| `docs/client/` | End-user and delivery documentation only. |

## Status rule

Requirement status starts as `Proposed` and changes only after implementation and verification evidence exists.
