# Requirements index

Detailed requirements live in one file per area. Each requirement is tracked by a stable ID and status.

## ID prefixes

- `REQ-UI-001`, `REQ-UI-002`, etc.
- `REQ-ARCH-001`, `REQ-ARCH-002`, etc.
- `REQ-TASK-001`, `REQ-TASK-002`, etc.
- `REQ-GOAL-001`, `REQ-GOAL-002`, etc.
- `REQ-POMO-001`, `REQ-POMO-002`, etc.
- `REQ-CAL-001`, `REQ-CAL-002`, etc.
- `REQ-SET-001`, `REQ-SET-002`, etc.
- `REQ-REP-001`, `REQ-REP-002`, etc.
- `REQ-PDF-001`, `REQ-PDF-002`, etc.
- `REQ-NFR-001`, `REQ-NFR-002`, etc.

## Statuses

- Proposed
- Approved
- In Progress
- Implemented
- Verified
- Blocked
- Rejected

## Template

```markdown
### REQ-AREA-001 - Requirement title

Status: Proposed

Objective:
Clear objective.

Checklist:
- [ ] Requirement approved
- [ ] UI planned or implemented if applicable
- [ ] State planned or implemented if applicable
- [ ] Domain planned or implemented if applicable
- [ ] Data/persistence planned or implemented if applicable
- [ ] Checks passed
- [ ] Documentation updated
- [ ] Traceability updated

Acceptance criteria:
- [ ] Criterion 1
- [ ] Criterion 2
- [ ] Criterion 3

Notes:
- Keep incomplete work as [ ].
- Only mark [x] after verification.
```
